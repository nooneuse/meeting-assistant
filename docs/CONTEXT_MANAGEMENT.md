# 有界会议上下文与响应提醒

> 术语更新（2026-10-28）：本文原有“会议”指独立的“议题”；议题集只组织目录，不共享原文、OCR 或模型上下文。当前目录、迁移和快捷键规则见 [TOPIC_COLLECTIONS.md](TOPIC_COLLECTIONS.md)。

状态：已实现并完成电脑 mock 验收。两套目录各 127 项核心测试 + 83 项 Android/Robolectric 测试通过，构建及 Lint 通过。本功能仅以 mock 服务、本机 HTTP fixture 及虚拟时钟验收，未调用真实模型、未操作手机。

## 产品约定

完整听写、轮次和 OCR 仍加密存档。每次请求只发送有界工作集；整理与告警不停止拾音、不改变 Auto 分段、不强制切换会议。达到阈值时非阻塞提醒新建会议，忽略提醒仍继续自动整理。已有答案保留，不反复追加为会议事实。

默认输入预算 12000、整理 / 长会议提醒阈值 75%、整理目标约 50%；首段可见答案等待超过 10 秒，在最近 3 个有效请求中出现至少 2 次时提醒。两种提醒共享每会议 10 分钟冷却。设置可调整预算、已知模型总窗口、输出预留、慢响应阈值和提醒间隔。总窗口已知时，实际输入预算自动取配置输入预算与「总窗口减输出及 1024 安全余量」的较小值。设置仅作用于后续请求，已提交的请求继续使用其配置快照。

无提供商 tokenizer 依赖：首版使用 UTF-8 字节数作为偏保守的 token 上界估计，并计入 JSON 包装、规则和偏好。它不是提供商实测 token 数，也不保证任意未知 tokenizer 的精确额度；本地发送硬上限针对这一估计。未知模型窗口允许手动配置。输入规则本身过大时明确报错，绝不静默裁剪偏好。

## 数据与工作集

- 完整记录：原有会议轮次 / 定稿段落 / OCR，不因整理而删除。
- 原文来源：稳定轮次 ID + 段落 ID；旧记录从轮次 ID 生成兼容引用。
- 有界会议记忆：最多 1500 估算 tokens，包含 topic / fact / constraint / correction / question 类别的原文摘录及来源。首版采用提取式摘要：模型只能选择完整来源段落的逐字引文，应用校验来源和全文相等，拒绝仅摘取半句而丢弃否定词；保留数字、单位、否定和代码。分类是辅助判断，不是新的事实。
- 覆盖水位：最后整理的来源 ID、前缀内容摘要，不保存无限增长的覆盖清单。识别纠正、恢复后内容不符时旧摘要失效。后台结果只有生命周期及原文版本仍有效才可提交。
- 工作集：规则与偏好、有限记忆、最新定稿、相关早期片段、最近有效 OCR。按总预算选取，所有引用均随请求提供；省略与不足显式标记。完整大代码块不从中间剪切。

过去问题优先按提问标记、时间和关键词选择原文片段，检索片段也受预算限制。首版使用本地原文选择，不增加云端检索或明文持久化全文索引。较早的资料未选中时不声称掌握全部会议。单个必要条目无法容纳时提示缩短题目 / 裁剪图像 / 调整预算，听写照常保留。

OCR 的文字块、坐标、角色推断及不确定性一起选取，优先当前图像；不将被排除图像重新引入。省略图像块时明确告知模型和用户，避免暗示题目完整。

## 后台整理与调度

每次构建请求先执行本地有界选择，再将较早原文和旧记忆组成另一个有界整理任务。回答优先；整理使用独立后台执行器和独立 provider 实例，每会议至多一个，有限超时及重试退避。不在音频回调中运行估算、JSON 解析或模型调用。

整理沿用当前文本服务，有额外用量，因此只在阈值到达且出现可整理的新内容时触发；失败保留已有有效记忆，工作集继续受到硬上限保护。取消 / 新会议 / 删除 / 关闭会取消整理，迟到回调不覆盖当前会议。冷恢复不恢复任何请求。

## 响应时间

时间起点为 provider 实际提交调用，分别记录首段可见答案及完整响应时间。空 delta / 心跳不算首段答案；取消或原文被纠正的请求不进入成功样本，超时可作为慢响应事件。统计按提供商与模型隔离，切换服务后重置；不将 OCR、排队和历史整理时间算作答案等待。

完整耗时用于诊断；长代码的完整生成较慢不会独自触发新会议提醒。延迟可能来自网络、推理或服务排队，不承诺新会议必然提速。服务明确返回 context-length 错误时只允许一次缩小预算重试，其他 HTTP / 额度错误不归因为上下文。

## UI 与新会议

状态行保留聆听状态，右侧按需出现无轮廓上下文提示图标。告警以短暂非阻塞提示条出现，提供「新建会议」与「继续当前」，不唤出已收起工具栏。图标可打开诊断详情：估算输入 / 上限、整理状态、遗漏范围、首段 / 完整耗时。

新建会议沿用现有确认及尾句收尾流程。默认只继承模型设置和回答偏好；可选择携带有长度上限的当前议题摘录。明确标为上场会议资料，不携带完整聊天或模型答案。提示、设置和详情支持简体中文与英文。

## 实现位置与边界

核心：`ContextSettings` 配置、`ContextMemory` 纯工作集规划与摘录验证、`ContextReport` 无敏感数据诊断；`SessionEngine` 管理独立整理生命周期、请求版本、首段 / 完整耗时与单次缩小重试。`MeetingManager` 从完整轮次恢复检索原文；记忆、覆盖水位与提醒消费状态随会议加密保存。`ContextUi` 提供设置、非阻塞提示条、状态行详情和可选议题延续。

首版记忆预算至多 1500 估算单位 / 24 条完整引文；每个整理批次至多检查 100 段，输入同样受总预算保护，最多一个任务，60 秒超时，最少 30 秒重试间隔。没有新旧内容可整理时不产生调用。无法容纳的完整段落不从中间截断，显式标记遗漏或提示用户调整预算。正文请求经提供商明确的上下文错误后最多缩小一次，较小预算在当前服务 / 模型下用于后续请求；改预算或模型会重置此自适应值。

完整档案和本地存储量不受模型请求预算裁剪。首版复用现有会议仓库，按本地原文做有界片段选择，不实现向量数据库或整场会议分页重构。整理不改变原有语音会话时长保护。模型实际摘要质量与端到端性能没有用真实服务验证；UTF-8 估算不等于提供商真实 token 数。

## Mock 验收

- 大量轮次、Auto 定稿及多个 OCR 下，每次回答和整理请求均小于总预算，原文存档不丢。
- 摘录结构错误、捏造引文、纠正原文、超时、失败、取消、重启、切换与删除时安全降级。
- 阻塞回答和整理期间持续送入 PCM；单例整理、冷却、虚拟长延迟均可确定性验证。
- 长答案不误报首段慢；不同服务统计隔离；上下文错误只有一次重试。
- UI 提示、详情、新会议及携带摘录、设置迁移 / 保存、布局重建和中英文全部采用 Robolectric mock 验证。
- 两套源码分别运行 core / Android 单元测试、构建与 Lint，开源目录扫描凭证。不连接手机、不请求真实模型。
